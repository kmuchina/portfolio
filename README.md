# kmuchina.com

The personal portfolio of Kennedy Muchina Kinuthia: a single-page static
site, generated by a small Go program and published at
<https://kmuchina.com>.

- **All content** lives in [`content/site.yaml`](content/site.yaml).
  To change it, read [`docs/EDITING.md`](docs/EDITING.md).
- **Design and engineering rules** live in [`CLAUDE.md`](CLAUDE.md).

## Stack

- **Go** (standard library, `html/template`), plus `gopkg.in/yaml.v3` and
  `golang.org/x/image` (image resizing).
- Hand-written **CSS** (custom properties, cascade layers) and small
  vanilla **JS**. No frameworks and no Node in the build.
- Everything is self-hosted: fonts (Fraunces, Inter, JetBrains Mono), icons
  (Lucide, Simple Icons) and images. There are no third-party requests.
- Optional: **`cwebp`** (the `webp` package) for WebP images. Without it the
  build still works and prints one warning.

## Commands

| Task | Command |
|---|---|
| Dev server on <http://localhost:8080> (rebuilds on refresh) | `make serve` |
| Everything CI runs: vet, tests, build, output check | `make ci` |
| Re-render the share image and icons from `design/` | `make og` |
| Build into `dist/` | `make build` |
| Colour contrast check (both themes) | `make contrast` |
| Tests only | `make test` |

Without `make`, use `go run ./cmd/serve`, `go run ./cmd/build` or `go test ./...`.
Go is at `~/.local/go/bin` on Kennedy's machine.

`make og` needs Playwright with Chromium. Either install it
(`npm install -g playwright && npx playwright install chromium`), or point
it at an existing copy:
`PLAYWRIGHT_MODULE=/path/to/node_modules/playwright-core make og`. It
rewrites `static/og.png`, `static/favicon.ico` and
`static/apple-touch-icon.png`; commit them afterwards.

## Deployment

**`main` is production.** Every push to `main` runs
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml):
vet and test → install `cwebp` → build → check the output → deploy to
GitHub Pages. If any step fails, nothing is deployed and the live site stays
as it was. Run `make ci` before every push.

- **Watching a run:** the repo's **Actions** tab.
- **Redeploying by hand:** Actions → *Deploy to GitHub Pages* → **Run workflow**.
- **The build writes** `CNAME`, `.nojekyll`, `robots.txt`, `sitemap.xml` and
  `site.webmanifest` itself. `dist/` and `.cache/` are never committed.
