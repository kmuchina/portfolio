# kmuchina.com

Personal portfolio of Kennedy Muchina Kinuthia: a single-page static site
generated by a small Go program. It uses the Go standard library plus
`gopkg.in/yaml.v3`, hand-written CSS and vanilla JS.

All content lives in [`content/site.yaml`](content/site.yaml). Design and
engineering rules live in [`CLAUDE.md`](CLAUDE.md).

## Requirements

- Go 1.22+ (the module targets the installed toolchain)

## Commands

| Task | With make | Without make |
|---|---|---|
| Build into `dist/` | `make build` | `go run ./cmd/build` |
| Dev server on :8080 | `make serve` | `go run ./cmd/serve` |
| Tests | `make test` | `go test ./...` |
| Colour contrast check | `make contrast` | `go run ./tools/contrast` |
| Static checks | `make vet` | `go vet ./...` |
| Remove `dist/` | `make clean` | `rm -rf dist` |

Both `cmd/build` and `cmd/serve` take `-content`, `-templates`, `-static` and
`-out`, all relative to the repo root. `cmd/serve` also takes `-addr` (default
`:8080`) and rebuilds whenever you request a page, so refreshing the browser
picks up changes. Invalid content fails the build with a numbered list of
every problem.

Design-system verification page: <http://localhost:8080/styleguide.html>

## Deployment

The site is published to GitHub Pages at <https://kmuchina.com>.

- **How it works:** every push to `main` runs
  [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml). It runs
  `go vet` and `go test`, builds the site into `dist/`, checks the output
  (`index.html`, `404.html`, `.nojekyll` and a `CNAME` of `kmuchina.com`),
  and then deploys `dist/` to Pages. The Go build writes `CNAME` (from
  `site.url`) and `.nojekyll` itself. `dist/` is never committed.
- **Run CI locally:** `make ci` runs the same steps in the same order
  (vet, test, build, output check). Run it before every push: `main` is
  production.
- **Watching runs:** the repo's **Actions** tab, or `gh run watch` from a
  terminal.
- **A failed run** deploys nothing. The live site stays exactly as it was
  until a later run succeeds.
- **Re-deploying by hand:** Actions → *Deploy to GitHub Pages* → **Run
  workflow** on `main`, or `gh workflow run deploy.yml`.
